# VeraTrace — shared data contract (proposed)

Written by Person 1 (frontend) as a starting point so all three of us agree on field names
before wiring real data in. Matches the shapes already used in `src/data/mockData.js` — the
UI is built against these exact field names, so if we change one here, the frontend needs a
matching update.

## Case

```ts
{
  caseId: string,        // unique id, generated by Person 3's backend
  title: string,
  status: 'OPEN' | 'IN_PROGRESS' | 'CLOSED',
  createdAt: string,     // ISO-8601
  updatedAt: string,     // ISO-8601
  evidenceCount: number,
  summary: string,
}
```

## Evidence record

Matches the schema Person 2's evidence module already produces:

```ts
{
  evidenceId: string,
  fileName: string,
  mimeType: string,
  sizeBytes: number,
  recordedAt: string,                 // ISO-8601, application-recorded only — not a verified incident time
  sha256: string,                     // 64-char lowercase hex
  verificationStatus: 'UNVERIFIED' | 'MATCH' | 'MISMATCH' | 'ERROR',
}
```

## Timeline event

```ts
{
  eventId: string,
  occurredAt: string | null,          // ISO-8601, or null if the time is unknown
  timeConfidence: 'confirmed' | 'uncertain',
  label: string,
  relatedEvidenceId: string | null,   // links back to an evidence record, if any
}
```

## What the frontend expects from pages

- Dashboard (`/dashboard`) needs a list of `Case` objects.
- Case overview (`/case/:caseId`) needs one `Case`, its `TimelineEvent[]`, and a short list of `EvidenceRecord[]` for the summary panel.
- Evidence workspace (`/case/:caseId/evidence`) needs the full `EvidenceRecord[]` for that case.

## Still to agree with Person 2 & Person 3

- Where `getCaseById`, `getEvidenceByCase`, `getTimelineByCase` (or equivalent) will actually live once they're backed by real data — an API client module, or data passed via routing state.
- Error/loading states for each of the above (the UI currently only models "found" vs "not found", via `EmptyState`).
- Whether case creation happens via a modal or a separate route — the Dashboard's "New case" button is currently a no-op placeholder.
